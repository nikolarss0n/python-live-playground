## Mock timing, disclosure and assessment

- The schedule is 5 minutes clarify, 5 plan, 30 implement, 15 test/debug, 5 explain. `useRefresherSession` derives these phases from persisted start time, with a 60-minute deadline.
- Variant selection prefers unused variants; once all three have been exposed, attempts are marked as retakes. This is disclosure-based practice, not a proctored or tamper-proof assessment.
- The variant is not selected until `startMock`; starting requires a successful persistent save. `contextFor` changes Day 13's follow-up at minute 30, and context-specific verification rejects results from the earlier phase.
- A Day 13 attempt submitted before the requirement change cannot complete the day. Finishing early does not cause the change to appear retroactively; the partial attempt remains reviewable.
- Submitted code is frozen. The store expires overdue attempts after navigation or reload and retains prior submissions and review rubrics when another attempt starts.
- Correctness comes from bounded behavior probes. Readability, edge cases, debugging and communication are explicitly self-reported review criteria. These are not automatic assessments of communication or asymptotic complexity.
- The Day 13 dependency variant now checks invalid later dependencies **before any handler effect**, including a boolean value that would otherwise resemble prior index zero. A mutation that moved validation into the execution loop is rejected.
- **Verified in the assembled desktop UI:** the start screen withholds the problem; active mock check details stay hidden; all six variants can be submitted and reviewed; used variants are labeled as retakes; submitted code resists editing. A second mock cannot start while another is running. The general coach and model runner remain absent after navigating to another learning track during the active mock.
- The browser test uses controlled time, not a one-hour wall-clock wait. A diagnosed Playwright 1.51 clock race briefly rolled `Date.now()` backward after `fastForward`, producing a false early submission. The verifier now serializes pause → advance → resume and asserts both retained global time and saved submission duration. Sixteen focused repetitions passed after this test-harness correction; application timing and the minute-30 completion rule were not weakened.
